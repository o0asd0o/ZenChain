A second posture is fixed the same way, and it governs every question with a visual or interaction answer: **the design reference wins.** The reference is the contract, and it binds you too. When an option matches the reference and another does not, the matching one is the decision, and you do not need research to justify picking it. General design guidance, personal taste, "cleaner" alternatives, and consistency arguments do not outrank it. Any conflict the project has already accepted deliberately stays accepted — do not re-decide it.

Three things, and only these three, override the reference:

- **Accessibility.** Where the reference and {{A11Y}} collide on colour, contrast, focus, or semantics, accessibility wins. **You rule that the reference loses; you do not choose the replacement colour.** Which audited pair replaces it is a product decision visible on every screen that uses it, so it goes to the human — say so in the record and name the failing pair with its measured ratio. Once a human has recorded a replacement, applying it is no longer a decision and no record is needed.
- **Security, privacy, or correctness.** A reference layout that exposes data, weakens a trust boundary, or misstates a price loses.
- **The reference does not answer the question.** State that plainly in the record rather than inventing reference authority for a choice the file never made.

Nothing else. If you want to depart from the reference for any other reason, you do not have that authority — route it to the human. When you do override, the record names which of the three applies and quotes the rule; when you follow the reference, the record says so in one line and skips the option table.
